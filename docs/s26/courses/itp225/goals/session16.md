## What We'll Do In Class

### Team Project Work

Chris won't be here on Wednesday, but you and your team should have everything
you need to get started. 

By the time we get back next week, every team should have at least:

- A repo, cloned on everyone's computer
- A .gitignore file that reflects all the lessons learned from last time
    - (At minimum, be sure to gitignore your db.sqlite3 file, .DS_Store, __pycache__, .venv)
- A license
- A README.md that includes each of your team members' names
- A wiki, with at least one page summarizing your team's understanding of 
the project requirements

If you also get to a minimal working Django that I can checkout and run, that's 
awesome.

As always, if you get stuck or need help, send me an email!

### Extensions

I know that some of the teams are excited and breaking ahead. If that's you, 
here are some notes about the next few things we'll be working on. Notice the theme:
we should be doing a ton of planning before we write any code. It's way easier 
to edit plans than it is to edit code!

- You should work hard to get a nice data model developed early. What data do
you think you'll need to collect, and how will you organize it? You should
get to a data model diagram that looks similar in structure to 
[the one that we looked at for the SQL Murder Mystery](https://mystery.knightlab.com/schema.png).
- Next, start thinking through the pages you'll need to make, what they'll
look like, and how they'll link to each-other. I like to document this via a 
[wireflow diagram](https://balsamiq.com/blog/wireflows/), which combines a flowchart
with drawings of what each page will look like.

For both of these, you should:
- Create an issue to track who is responsible
- Put the result in your wiki
