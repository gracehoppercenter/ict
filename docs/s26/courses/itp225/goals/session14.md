## What We'll Do In Class

### Stand Up

As is our new routine, we'll start class with a standup meeting.

This time, I want to focus on providing appropriate context for our updates. Your update should still be short, but should include enough detail for someone outside your team to understand it. Instead of saying "I worked on a form," say something like "I worked on the view and template that allow a user to create a new task". If your summary is vague, I'll assume that means you didn't do much...

### Project assignment

We've settled on four projects that we'd like to take on this year, so we'll need to form four teams. (note: we reserve the right for team assignments to be fluid. We want you to take the lead in forming teams, but we might need to tweak as the year goes on, for a variety of reasons).

First, we'll talk about the ACC Reservation Systems. This project is a little special because it's in-progress. We really need these two projects to be fantastic by the end of the school year. Whoever takes on this project will be held to a high standard, and will have a different focus (because CRUD already works for both apps). This team will focus on testing, refactoring for code reusability (maybe even collaborating to share apps with the book reservation system that Ben, Kara, and Josh are working on), and deployment. We'd like to staff this project with folks who are feeling very confident with Django and are interested in this kind of work. I'm hoping that folks will self-identify.

### Team Project Work

Then we'll return to our teams for our current project. Our goal will be to get these projects to a point where we can run and present them live in class on Monday.

Hopefully your projects will be close to finalized by the end of class. Give each group member a small finishing-touches issue to 
work on for homework. We'll take ~10 minutes at the beginning of next class to merge PRs, and then we'll present.
